# design-sync notes — website-launchpad

Repo-specific gotchas for syncing this design system to claude.ai/design.
Read this before re-running the sync.

## What makes this repo unusual

It is a **Next.js app, not a published component library**. Nothing here ships a
`dist/` or a `.d.ts` tree, and `globals.css` is raw Tailwind source. The
converter expects a built package, so `.design-sync/build-inputs.mjs`
(wired as `cfg.buildCmd`) manufactures both inputs before every build:

- `dist/types/` — declarations emitted via `.design-sync/tsconfig.dts.json`.
  Without them every `<Name>Props` degrades to `[key: string]: unknown` and the
  design agent gets no API to code against.
- `.design-sync/.cache/globals.compiled.css` — Tailwind compiled to static CSS,
  with the remote font urls rewritten to local files (see Fonts below).

`cfg.buildCmd` also runs `.design-sync/gen-docs.mjs`. Both must run before
`package-build.mjs`; the driver does this for you.

## The design-system surface is declared, not discovered

`.design-sync/ds-entry.ts` is the bundle entry. It re-exports the repo barrel
(`src/components/index.ts`) **plus** the shadcn-style primitives that
`CLAUDE.md`'s Component Quick Reference documents but the barrel omits (Badge,
Accordion, Dialog, Tooltip, Separator, VideoDialog, SlideIn).

`cfg.componentSrcMap` pins all 43 components explicitly. This is deliberate,
not laziness: with no shipped `.d.ts`, the converter's name-based discovery
finds nothing, and passing an explicit entry disables its synth-entry fallback.
**When a component is added to `src/components/`, add it to both files** or it
will silently not sync.

Scope decision (2026-08-05): `src/components/admin/` and
`src/components/shortcodes/` are intentionally excluded — internal tooling and
CMS plumbing, not design surface. `JsonLd` is excluded via a `null` entry
(renders an invisible `<script>`).

## Next.js shims

`.design-sync/tsconfig.ds.json` aliases four Next modules to static shims in
`.design-sync/shims/`, and the converter reads `compilerOptions.paths` from
**that file only** (it does not follow `extends`), so every alias — including
`@/*` — must be declared there in full.

- `next/image` → plain `<img>`. The real one routes through `/_next/image`,
  which does not exist outside a Next server, so every image in every design
  would 404. Internal only: no exported component re-exports `Image`.
- `next/link` → `<a>`; `next/navigation` → neutral hook stubs;
  `next/dynamic` → `React.lazy` + `Suspense`.
- `shims/process-global.ts` installs a minimal `process` and **must stay the
  first import in ds-entry.ts** — Next internals and prismjs read
  `process.env.*` at module-init time, and without it the bundle throws
  "process is not defined" before assigning a single export, blanking all 43
  components.

Removing the shims re-inflates the bundle from ~1.1 MB to ~1.4 MB and breaks
every preview.

⚠️ **A JSON file with a `"//"` key breaks the converter.** Its comment-stripping
regex mangles `"//": "..."` into invalid JSON and `tsconfigPathsPlugin` then
returns null _silently_ — aliases stop resolving with no error. Use real `//`
line comments in `tsconfig.ds.json` instead. This cost a debugging cycle.

## Fonts

`globals.css` loads Moderat from `static.pingcap.com` and says local font files
are "forbidden" — that rule is about the WordPress site, not this bundle. The
5 woff2 files are committed at `.design-sync/fonts/` and `build-inputs.mjs`
rewrites the CDN urls to them, so designs never depend on a network fetch.
Approved by Liya on 2026-08-05.

If the brand font is ever revved, re-download into `.design-sync/fonts/` —
`build-inputs.mjs` fails loudly if a referenced file is missing.

## Grouping and docs

`cfg.docsDir` points at `.design-sync/docs/`, generated by `gen-docs.mjs` from
the repo's own `.ai/skills/design-system/components.md` and `docs/sections.md`,
split per component. Two reasons it exists:

- **Grouping.** The converter treats `ui` as a generic directory name, so
  without `category` frontmatter all 22 primitives land in a group literally
  called "general". The stubs set `category: UI` / `category: Sections`.
- **Prose.** 28 of 43 components have real documented specs in those files.
  Binding them lifted total `.prompt.md` content from ~13 KB to ~53 KB.

A frontmatter-only stub is fine — the converter appends the synthesized
`## Props` when the doc body has no props section of its own.

## Preview authoring

- **Import components by specific module path** (`@/components/sections/HeroSection`),
  never `from '@/components'` — that alias resolves to a _directory_ and the
  preview fails to compile with `Cannot read file "src/components": is a directory`.
- Wrap section previews in `<SectionWrapper style={{ background, spacing }}>` —
  the repo's own idiom, as used in `src/app/sections/page.tsx`.
- **`src/app/sections/page.tsx` is the single best source of composition data**:
  a `demoRenderers` map with DS-team-authored canonical examples for ~13
  sections. Port from there before inventing.

### The dark-canvas provider

`cfg.provider` = `DsCanvas` (`.design-sync/shims/ds-canvas.tsx`). The design
system is dark-first (`body { @apply bg-bg-primary text-text-inverse }`), but
preview cards hard-code `body{background:#fff}` in their own template, which
beats that `@layer base` rule — leaving white-on-white text. `DsCanvas` restores
the real surface. It affects **preview cards only**; designs built in Claude
Design get the dark body straight from `styles.css`.

### Viewports

`cfg.overrides` sets a viewport per scoped component. This is load-bearing, not
cosmetic: at the default narrow viewport, `columns={4}` and `columns={3}` both
collapse to 2 and the variant axis stops varying — the cards look identical and
fail the "Plausible" rubric. Sections use `1280x760` + `cardMode: "column"`;
atoms use compact viewports so a button is not stranded in 100vh of black.

Changing `cfg.overrides` invalidates the stamped build: `preview-rebuild.mjs`
refuses with `[CONFIG_STALE]` until `package-build.mjs` runs again.

## Capture-harness races (bit every batch — read before authoring)

`package-capture.mjs`'s `settle()` awaits fonts and image decode only. It does
**not** wait for animation, so anything time-based is photographed mid-flight:

- **`CountUp` captures mid-animation.** An authored `"10x"` screenshotted as
  `7x`, `"3,000+"` as `2,198+`, `"$2,000+"` as `$1,503+`. The numbers are
  plausible, so this fails silently — the card ships a _wrong metric_.
  Workaround used in `StatsSection`: pick values `CountUp`'s parser
  (`^([^0-9]*)([0-9,]+)([^0-9]*)$`) rejects and passes through verbatim —
  anything with a second digit group (`8.5x`, `99.99%`, `24/7`, `2.4 PB`).
  A real fix is a settle delay (~1600ms) or a reduced-motion path in `CountUp`.
- **`SlideIn` / IntersectionObserver** (CtaSection, TestimonialsSection,
  HeroSection, FeatureMediaSection) is a 700ms fade that can capture
  transparent. `FeatureMediaSection` defaults to `animate: true` — pass
  `animate={false}` in previews.
- **Captures are `fullPage: false`.** A composition taller than its viewport is
  sliced at the bottom with no warning — `CaseStudyCardsSection` lost its CTAs
  until its override was raised to `1280x1000`. Check the sheet, don't assume.

## ⚠️ Recompile CSS _after_ authoring previews — ordering matters

`package-build.mjs` does **not** run `cfg.buildCmd`; you run it. So if previews
are authored after the last `build-inputs.mjs` run, Tailwind never scanned them
and any class used _only_ in a preview is purged — the card then renders with
that rule silently missing. It cost a debugging cycle here: `Separator`'s `my-6`
vanished and the divider looked cramped; a `w-[420px]`/`h-[236px]` thumbnail
ignored its sizing entirely and clipped.

**Always re-run `node .design-sync/build-inputs.mjs` after writing or editing
previews, before the final `package-build.mjs`.** Note this is invisible to the
grade lifecycle: styling churn deliberately does _not_ clear grades, so a
carried-forward `good` can be describing a sheet shot against stale CSS. After
a recompile, re-read the sheets of anything using preview-only classes.

## The Tailwind safelist is load-bearing

`.design-sync/tailwind.ds.config.ts` carries a `safelist` covering the design-token
families (semantic colours, the brand/carbon ramps, the type scale, layout
widths). It is not belt-and-braces.

JIT emits only classes the repo _currently uses_. But the design agent composes
**new** layouts and reaches for valid tokens no existing page happens to use —
`max-w-content-sm`, `border-border-strong` and the full brand ramp were all
absent from the shipped CSS before the safelist, so any design using them would
have rendered unstyled with no error anywhere. Cost: ~11 KB (101 → 112 KB).

**If a token is added to `tailwind.config.ts`, extend the safelist pattern too**,
otherwise it exists in the theme but never reaches a design. Verify with
`grep -cF ".<class>" ds-bundle/_ds_bundle.css`.

## Images in previews

**Repo-local `/images/...` paths 404 in previews.** The preview server serves
`ds-bundle/`, which has no `images/` dir, and the `next/image` shim emits a raw
`<img src>`. This is a trap because `src/app/sections/page.tsx` — the best
composition source — uses local paths. Rewrite them to
`https://static.pingcap.com/launchpad/images/<path>` (the repo's own
`resolveCdnUrl` mapping); absolute `static.pingcap.com` URLs load fine.

Also: the shim emits `width`/`height` as HTML attributes and Tailwind
preflight's `max-width:100%; height:auto` then governs the box, so passing
_intrinsic_ dimensions makes images fill their container and clip at a fixed
capture viewport. Pass display-scale values.

## Known degraded prop contracts

`Accordion`, `Dialog`, `Separator`, `Tooltip` still emit
`[key: string]: unknown` — they re-export Radix primitives whose props the
extractor cannot flatten. Their real API is documented in their `.prompt.md`
(sourced from `components.md`), so the design agent is not flying blind. Fix
with `cfg.dtsPropsFor` if it ever matters.

`Header`/`Footer` genuinely take no props and carry a `cfg.dtsPropsFor` note
saying so.

**Name collisions with `src/lib/dsl-schema.ts`.** That file exports a `<X>Props`
interface for most sections (the DSL page-renderer's shape), and the extractor
searches _all_ files and takes the first match — so a component whose own props
interface shares that name can publish the wrong contract entirely. Seven names
collide (`FeatureCard`, `Agenda`, `Speakers`, `ComparisonTable`,
`RichTextBlock`, `CodeBlock`, `TableOfContents`); three were actually wrong and
now carry `cfg.dtsPropsFor` overrides:

- `FeatureCard` — shipped `FeatureCardSection`'s shape (`items`/`columns`/
  `borderStyle`) instead of `icon`/`title`/`description`/`href`.
- `TableOfContents` — lost `tone`.
- `ColumnsSection` — props `extends ColumnsProps` from `dsl-schema`, and
  inherited cross-module members are dropped; it shipped only `className`.

**If a component is added to `dsl-schema.ts` with a name matching a real
component, re-check its emitted `.d.ts`.** The failure is silent: the file is
valid TypeScript, just describing a different component.

The `types` field added to `package.json` points at `dist/types/index.d.ts`
(generated). It exists purely so the converter's fallback prop resolution can
reach components whose props interface is named differently from the component
— e.g. `FeatureGridSection` takes `FeaturesGridProps`. Removing it silently
degrades 5 components back to `[key: string]: unknown`.

## Re-sync risks

- **`componentSrcMap` and `ds-entry.ts` are hand-maintained enumerations.** New
  components in `src/components/` will NOT appear until added to both. Check
  `git diff` on `src/components/` against the map before trusting a re-sync.
- **`gen-docs.mjs` parses markdown by heading.** If `components.md` or
  `docs/sections.md` is restructured (headings renamed, components merged into
  shared sections), docs silently stop binding and `.prompt.md` files shrink
  back to props-only. The build log line `docs: N/43 components matched` is the
  canary — if N drops, that is why.
- **Font files are a committed copy.** They will not track a rebrand.
- **Tailwind content globs.** `.design-sync/tailwind.ds.config.ts` scans
  `src/**` plus `.design-sync/previews/**`. A utility class used _only_ in a
  preview outside those globs gets purged and the card renders unstyled.
- **The `next/*` shims are a fidelity trade.** They are prop-compatible, but if
  a component starts relying on real Next behaviour (an actual router, image
  optimization, `usePathname` returning a real path) the preview will diverge
  from production. `usePathname()` always returns `/`, so active-nav states
  never highlight in previews.
- **Only the 24 scoped components were preview-authored and graded.** The other
  19 ship on the floor card or a bare default render — correct by design, and
  authorable on any later re-sync.

## Doc bugs found while authoring (in the repo's own docs, NOT fixed)

Reported to Liya 2026-08-05; left alone because they are product docs, not sync
inputs. They matter here because `gen-docs.mjs` feeds these files straight into
each component's `.prompt.md`, so the design agent reads them:

- `CLAUDE.md`'s component table lists `background="red|violet|blue|teal"` as a
  `CtaSection` prop. **`CtaSection` has no such prop** — the colour comes from
  the wrapping `SectionWrapper`.
- `.ai/skills/design-system/components.md` documents `SectionHeader`'s prop as
  `label`; it is actually `eyebrow`. It also claims `align` defaults to
  `center`; the default is `left`. And it omits `FeatureCard`'s `ctaText`.

## Shipped-design observations (not defects — do not "fix" in previews)

- `Tabs` inactive labels render `text-carbon-900` (#28333E) on black and are
  very nearly invisible. That is the shipped design.
- `ComparisonTable` double-contains itself — its own `max-w-container
px-container` sits inside `SectionWrapper`'s `.contain`, ~104px inset per
  side at 1280. Shipped behaviour: `src/lib/page-renderer.tsx` wraps every
  section uniformly.
- `globals.css:720` sets `.animate-logo-marquee { transform: translateX(100%) }`
  under `prefers-reduced-motion`. Playwright defaults to `no-preference` so it
  does not fire — but adding `reducedMotion: 'reduce'` to the capture context
  would render `LogoCloudSection` empty.

## Coverage gaps in authored previews

- `ColumnsSection` `mediaType: 'shortcode'` and `'video'` — both resolve to
  posterless autoplaying `<video>` elements that screenshot as black
  rectangles. Would need poster frames to be gradable.
- `ColumnsSection` and `ComparisonTable` have **zero real usages** anywhere
  under `src/app/**` and are absent from `demoRenderers`; their previews are
  derived from source + `src/lib/section-registry.ts` defaults rather than
  ported from a shipped page. Worth a human eye.

## Deliberate exclusions

- **`HubSpotForm`** — `componentSrcMap.HubSpotForm: null`. It is the bare embed
  primitive: it renders an empty container until HubSpot's external script
  resolves, so there is nothing to preview and the card was a blank rectangle.
  It is not in `CLAUDE.md`'s documented component surface either. **It is still
  exported from the bundle** via `ds-entry.ts`, so `window.WebsiteLaunchpad.HubSpotForm`
  works — it simply has no card or `.d.ts`. Use `FormSection` (which wraps it and
  supplies the heading) instead.
- `FormSection`'s preview has only a `WithHeading` cell; a heading-less variant
  captures blank for the same reason.

⚠️ `cfg.overrides.<X>.skip` takes an **array of story names**, not a boolean.
`skip: true` crashes the build with `TypeError: boolean true is not iterable`
in `emit.mjs` and leaves `ds-bundle/` half-written — re-run the build after
fixing. It is not a way to exclude a whole component; use `componentSrcMap: null`
for that.

## Reviewing locally

```sh
node .ds-sync/storybook/http-serve.mjs ./ds-bundle   # then open /.review.html
```

`ds-bundle/.review.html` iframes every card as the product renders it. The
per-cell grading sheets are in `ds-bundle/_screenshots/review/`, and the
whole-set contact sheets in `ds-bundle/_screenshots/`.

## Known render warns (triaged — not new)

- `IconFeatureItem` — `[RENDER_THIN]`, unauthored atom that renders only its
  own label at default props. Expected; authoring its preview would clear it.
- Unauthored components reported as "floor card" are the deliberate baseline,
  never a failure.
